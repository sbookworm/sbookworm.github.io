2017年，Google发表了一篇论文，标题很霸气——**《Attention Is All You Need》**。这篇论文推出了一个叫**Transformer**的模型结构，直接奠定了往后七年所有大语言模型（LLM）的根基。

但有意思的是：**今天的LLM，其实只用了Transformer的一半。** 这不是偷工减料，而是一场深思熟虑的"断臂"。这篇文章就来聊聊，原始Transformer长什么样，现在的LLM又做了什么改变，以及为什么要这样改。

<!-- more -->

## 一、原始Transformer：一个"翻译员"的解剖图

Transformer最早是为了**机器翻译**设计的。翻译这件事，本质上是一个序列到序列（Seq2Seq）的转换过程：输入一串英文，输出一串中文。

为了完成这件事，原始Transformer设计了两大块：

### 1. 编码器（Encoder）——"消化理解"阶段

编码器的任务是**理解**输入的句子。它先把每个词变成一个向量（一串数字），然后让这些向量互相"打招呼"——这就是**自注意力机制（Self-Attention）**：每个词去看看句子里的其他词，跟谁关系近就跟谁多聊聊。

比方说翻译"The cat sat on the mat"（猫坐在垫子上）：

- 当处理"sat"这个词时，模型会注意到它跟"cat"（猫）和"mat"（垫子）关系很紧密——它们共同描述了"猫坐在垫子上"这个场景
- 而"The"这种虚词，虽然语法上不可或缺，但实际含义没那么重

自注意力机制就是这样让每个词动态地决定应该"关注"句子里的哪些其他词。

### 2. 解码器（Decoder）——"组织语言"阶段

解码器负责**生成**输出句子。但它有一个特殊限制：**不能偷看答案后面的内容**。

这叫**掩码注意力（Masked Attention）**——在生成第N个词时，只能看第1到第N-1个词，不能提前知道第N+1、N+2个词是什么。这就像写作文，你写完上一句再想下一句，不能先写完再倒过来改。

此外，解码器还有一个**交叉注意力层（Cross Attention）**，专门用来"参考"编码器的输出。编码器把原文理解透了，解码器就时不时回头查一下编码器的结果，确保翻译得准确。

```
原始Transformer结构（以翻译为例）

  输入: "The cat sat on the mat"
       ↓
  ┌─────────────────────┐
  │   Encoder 堆叠 (N层) │  ← 理解原文：词与词之间互相"看"，建立关系
  │  • Self-Attention  │
  │  • Feed-Forward     │
  └─────────────────────┘
       ↓ （输出对原文的深度理解）
       ↓
  ┌─────────────────────┐
  │   Decoder 堆叠 (N层) │  ← 生成译文：一个词一个词往外蹦
  │  • Masked Attention │  ← 只能看之前生成的词
  │  • Cross Attention  │  ← 参考Encoder的理解结果
  │  • Feed-Forward     │
  └─────────────────────┘
       ↓
  输出: "猫 坐在 垫子上"
```

## 二、GPT时代：只留一半，反而更强

时间来到2018-2019年，OpenAI的GPT-1、GPT-2，以及Google的BERT相继问世。它们都不约而同地**只使用了Transformer的解码器（Decoder）部分**，把编码器彻底扔掉了。

BERT用的是编码器（Encoder），走的是"完形填空"路线；GPT系列用的是解码器（Decoder），走的是"续写"路线。后来证明，**纯解码器架构更适合Scaling Up**——模型越大，效果越好，这条路最终走出了ChatGPT和GPT-4。

```
纯解码器（Decoder-Only）架构

  输入: "从前有座山，"
       ↓
  ┌─────────────────────┐
  │  Decoder 堆叠 (N层)  │  ← 所有层都是"自己看自己"
  │  • Masked Attention │    （只能看之前生成的词）
  │  • Feed-Forward     │
  │  • Masked Attention │
  │  • Feed-Forward     │
  │         ...         │
  └─────────────────────┘
       ↓
  输出: "山上有个庙，庙里有个老和尚在讲故事……"
```

这时候你可能有个疑问：**没有编码器，模型怎么理解输入？**

答案是：**靠"续写"本身来理解。** 解码器在生成每一个新token时，都会通过注意力机制回顾之前所有的token——包括输入的那部分。所以它并不是"不理解输入"，而是把输入也当成"已经生成好的文本"来处理。

## 三、关键差异对比

| 对比维度 | 原始Transformer（Encoder-Decoder） | 现代LLM（Decoder-Only） |
|------|------|------|
| **设计初衷** | 机器翻译等Seq2Seq任务 | 大规模语言模型（续写/对话） |
| **输入处理** | Encoder先完整理解输入，再交给Decoder | 输入和输出一起塞进Decoder，顺序处理 |
| **注意力方向** | Encoder双向（前后都能看）；Decoder单向（只能看之前） | 全局单向（生成时只能看历史） |
| **交叉注意力** | 有（Decoder"参考"Encoder的输出） | 无 |
| **典型应用** | 翻译、摘要、问答（需要理解+生成） | 聊天、写作、代码生成、推理 |
| **扩展规律** | 规模收益有上限 | 大力出奇迹，Scaling Law效果显著 |

## 四、为什么LLM选择了"断臂"？

### 1. 架构统一，训练更简单

Encoder-Decoder结构实际上是**两个模型拼在一起**：前面一个理解，后面一个生成。训练的时候也要分别训练，流程复杂。

纯Decoder只有一个模块，它的任务是**给定一段文本，预测下一个词**。这个任务简单粗暴，也叫**语言建模（Language Modeling）**——整个互联网的文本都能用来训练，天然就适合大数据。

> **类比：作家 vs 翻译员**
>
> Encoder-Decoder像一位翻译员：他先通读一遍原文（理解），再着手翻译（生成）。而纯Decoder更像一个作家：拿起笔就开始写，写到哪算哪，但每写一句都会回头检查前文——因为他需要保持前后逻辑一致。
>
> 互联网上的文本绝大多数都是"作家"的产出，而不是"翻译员"的产出。用作家的大量作品来训练，效果自然最好。

### 2. Scale up更容易

当你把模型从10亿参数扩展到1000亿参数时，**架构的简洁性**至关重要。Decoder-Only没有Encoder-Decoder之间的复杂交互，参数利用率更高，也更容易分布式训练。

OpenAI在GPT-2之后就发现：只要数据够多、模型够大、训练够久，纯Decoder架构的"续写"能力可以涌现出惊人的智能——包括Few-shot学习、推理能力、甚至思维链。

### 3. 生成质量更高

Decoder-Only架构有一个内在优势：**它训练时的任务和推理时的任务完全一致**——都是"给定上文，生成下文"。而Encoder-Decoder训练时理解是理解的，生成是生成的，存在任务不一致的gap。

## 五、总结：一句话说明白

原始Transformer是一个为**翻译**量身定制的双塔结构（Encoder + Decoder），而现代LLM只保留了Decoder这一半，把它训练成一个**超级"文字接龙"高手**。

这个"断臂"并不是退化，而是一次**战略聚焦**：放弃通用翻译的幻想，专心把"续写"这件事做到极致——然后发现，当续写能力足够强时，它几乎能做所有事情：聊天、编程、写作、分析、推理……

这大概就是深度学习里最经典的哲学之一：**有时候少就是多。**
